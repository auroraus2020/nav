# ADR-001：坚持单文件、零构建、零依赖

- 日期：2026-10-13（追认既有事实并固化）
- 状态：已采纳

## 背景

AURORAUS 导航是一个个人网址导航主页，需要长期维护（数年）并在任何环境打开即用：本地双击、U 盘、任意静态托管、朋友下载一个文件夹就能跑。项目当前形态是 `index.html` 单文件承载全部结构/样式/逻辑（约 5600 行），外加 `config-editor/`、`help/` 两个纯静态子页。

## 决策

继续**不引入任何 npm 依赖、打包器、前端框架或 CDN 资源**，用原生 HTML/CSS/JS（以 ES5 兼容写法为主）实现全部功能；新增能力也照此办理。

## 理由

1. **分发成本为零**：整个站点就是一堆静态文件，复制目录即部署，不需要 `npm install` 或构建产物。
2. **十年可维护**：没有依赖就不会有依赖腐化（框架大版本升级、供应链风险、锁文件失效）。单文件用编辑器打开就能改。
3. **离线可用**：无 CDN 意味着断网也能正常渲染（壁纸与图标都在本地 `assets/`）。
4. **`file://` 直接可用**：避免 ES module 与 `fetch` 读本地文件的限制，用户不必起服务器。
5. **改造成本可控**：功能规模（一个导航页 + 一个编辑器）远未到需要框架的复杂度。

## 代价与已知取舍

- 站点数据出现**两份拷贝**（`index.html` 手写卡片 + `config-editor/data.js` 默认值）。缓解手段：`tools/verify_config_sync.py` 做一致性硬门禁（见 `PROJECT_STATUS.md` 技术债）。
- 新增分类需要**手动登记 6 处**（正文/侧边栏/移动端 Tab/设置面板/导出数组/帮助文档）。缓解手段：`tools/verify_site_integrity.py` 断言这 6 处。
- 单文件体积较大（`index.html` 约 250 KB）。对本场景（本地/内网打开）无实际影响。
- 无类型检查与单元测试框架，改用「无头 Chrome 真实页面断言」（`tools/run_ui_tests.py`）作为等价的可执行验证。

## 何时应重新评估

出现下列任一情况时应重开此决策：站点数超过 ~1000 或分类数超过 ~40（手写卡片不可维护）；需要多人协作编辑数据；需要服务端能力（登录、云端同步、统计）。
